# Уроко — мастерская репетитора

Приложение для подготовки уроков по школьным предметам и к ОГЭ/ЕГЭ. Один материал доступен в трёх связанных видах: план с конспектом, майнд-карта и презентация. Теперь есть серверная ИИ-генерация по словесному описанию и рекомендации по составлению запросов.

## Как пользоваться ИИ

Нажмите **«Создать с ИИ»**, выберите формат, укажите предмет, класс, экзамен и длительность, затем опишите задачу словами.

1. **Стратегия на учебный год — «Программа».** Опишите полную программу, исходный уровень ученика, цель, срок подготовки, число и частоту занятий. Попросите диагностику, последовательные модули, повторение, контрольные точки и самостоятельную работу. Результат — программа с распределением количества занятий по модулям. Это не один урок с таймингом на год. Из модуля можно отдельно создать подробный урок кнопкой «Создать урок».
2. **Отдельный урок — «Один урок».** Укажите конкретную тему и желаемый план обычными словами: что объяснить, на каких примерах, как потренировать и проверить понимание. Назовите типичные ошибки ученика и время урока. Результат — цель, этапы, содержательный конспект, задания и домашняя работа. Карта и слайды строятся из него автоматически.
3. **Тема на несколько встреч — «Серия занятий».** Задайте от 2 до 6 занятий и порядок тем. Получится несколько отдельных редактируемых уроков с постепенным усложнением.
4. **Подготовка к ОГЭ/ЕГЭ.** Укажите навыки и актуальные требования, если они важны. У модели нет доступа к текущим материалам ФИПИ: она не должна утверждать обратное. Перепроверьте номера, критерии, решения и арифметику перед уроком.
5. **Адаптация под ученика.** Опишите, что уже получается, где возникают ошибки, какой темп и способ объяснения подходят. Не включайте ФИО и другие ненужные личные данные.

Примеры доступны прямо в окне ИИ. Перед добавлением результат показывается на просмотре. Можно уточнить описание, проверить материал и только потом добавить его в библиотеку; существующие материалы не заменяются. Генерацию можно остановить. Черновики ИИ требуют проверки преподавателем.

## Запуск

Нужен **Node.js 24.5+**. Для запуска приложения не нужны зависимости и сборка:

```sh
npm start
```

Сервер по умолчанию слушает только локальный интерфейс на порту 8000. Он отдаёт интерфейс и `/api/ai/*`. Для другого порта установите `PORT`. `npm start` читает локальный `.env`, если он есть, и поддерживает стандартный HTTPS-прокси и системные доверенные сертификаты.

Без ключа **ручной редактор продолжает работать**, а ИИ явно сообщает, что не подключён. Заготовки не выдаются за результат генерации. Старый статический запуск через Python тоже работает для редактора, но не предоставляет ИИ-сервер.

### Подключение настоящей генерации

1. Создайте локальный `.env` по образцу `.env.example` или задайте переменные в защищённых настройках хостинга.
2. Добавьте `TUTOR_AI_API_KEY` — ключ OpenAI API. Не вставляйте его в браузер, исходники, GitHub или чат. Доступ к ChatGPT не заменяет ключ и биллинг API.
3. При необходимости задайте `TUTOR_AI_MODEL`; по умолчанию используется `gpt-4.1-mini`. Модель должна поддерживать Responses API и Structured Outputs.
4. Перезапустите `npm start` и проверьте генерацию из интерфейса.

Запрос идёт **браузер → сервер Уроко → OpenAI Responses API**. Ответ проверяется до добавления: структура, число материалов и сумма минут/занятий. Некорректный или незавершённый ответ не меняет библиотеку. Ответы запрашиваются с `store: false`; это не обещание отсутствия иной обработки или хранения на стороне провайдера. Сервер приложения не сохраняет описания и ответы на диск и не пишет ключи или промпты в журнал.

Для публичного сервера необходим `TUTOR_AI_ACCESS_CODE` длиной от 12 символов. Репетитор вводит его в разделе «Подключение ИИ». Код остаётся в памяти открытой страницы; он не сохраняется в библиотеке или localStorage. Это общий код доступа для пилота, не полноценная система аккаунтов. Есть ограничения частоты (8 генераций в минуту на адрес), два одновременных запроса и таймаут 90 секунд. На многопроцессном или многосерверном развёртывании ограничения нужно вынести в общее хранилище; текущие лимиты действуют в одном процессе.

## GitHub Pages и размещение сервера

Редактор: https://lenich3-lab.github.io/123qwerty/

GitHub Pages публикует только статические файлы и **не запускает Node.js**. Поэтому одного push недостаточно для работы ИИ. Есть два варианта:

- Разместить весь проект на Node-хостинге: интерфейс сам найдёт свой сервер.
- Оставить интерфейс на Pages, разместить сервер отдельно и указать его HTTPS-адрес в «Создать с ИИ → Подключение ИИ». На сервере разрешить origin `https://lenich3-lab.github.io` через `TUTOR_AI_ALLOWED_ORIGINS` (без пути `/123qwerty` и без завершающего слеша).

Подготовлен [render.yaml](render.yaml). Инструкция: [развёртывание и проверка](docs/deployment.md). Файл конфигурации сам по себе ничего не развёртывает. Ключ и доступ к хостингу не включены в репозиторий.

## Экспорт в PDF

В меню **«Экспорт»** выберите **«Майнд-карта → PDF»** или **«Презентация → PDF»**. Кнопки PDF также есть на вкладках карты и презентации. Откроется отдельное окно: нажмите **«Сохранить PDF»** и выберите в диалоге печати **«Сохранить как PDF»**. Отключите колонтитулы браузера.

Карта вписывается целиком в один лист A4; ориентация выбирается по форме карты. Очень большая карта будет уменьшена — для редактируемого векторного оригинала остаётся SVG. Презентация сохраняется целиком, по одному слайду на страницу A4 в альбомной ориентации, с выбранным оформлением. Масштаб карты в редакторе и выбранный слайд не ограничивают экспорт. Сервер и ключ ИИ для PDF не нужны.

## Редактор и хранение

- Библиотека с поиском, созданием, копированием и удалением; редактируемые примеры по математике, русскому и биологии.
- Предмет, класс, формат подготовки, цель, домашняя работа и личные заметки.
- Этапы урока с минутами или модули программы с количеством занятий; добавление, перестановка, дублирование и удаление с подтверждением.
- Майнд-карта с масштабированием и переходом к редактированию, три темы презентации, показ со стрелками. Личные заметки в слайды не включаются.
- Экспорт плана для печати/PDF, карты в PDF/SVG, презентации в PDF и автономный HTML и редактируемых материалов JSON. Импорт JSON добавляет копии, не заменяя текущие записи.

Материалы хранятся в `localStorage` текущего браузера и адреса сайта (`uroko.workspace.v1`). Старые уроки совместимы с новой версией. Между устройствами, браузерами и разными адресами сайта данные не синхронизируются. При переезде на хостинг сначала экспортируйте библиотеку в JSON, затем импортируйте её по новому адресу. Очистка данных сайта удаляет библиотеку; регулярно скачивайте резервную копию. При ошибке сохранения материалы в открытой вкладке доступны для экспорта. Не редактируйте одну библиотеку одновременно в нескольких вкладках: сохраняется последняя записанная версия.

При повреждённых данных приложение показывает примеры и предупреждение, не изменяя исходную запись до следующего сохранения. Перед новой записью исходные данные сохраняются в `uroko.workspace.v1.recovery`.

Максимум 100 материалов в библиотеке, 40 этапов/модулей в материале и 2 МБ для импортируемого файла. В этой версии нет аккаунтов, облачной синхронизации библиотеки, общего банка проверенных задач, совместного редактирования и экспорта в PPTX.

## Проверки

```sh
npm ci
npx playwright install chromium
npm run check
npm test
```

Если Chromium установлен в `/usr/bin/chromium`, тесты используют его. Другой путь — через `CHROMIUM_PATH`. Тестовые серверы запускаются на свободных локальных портах и закрываются автоматически.

Тесты покрывают редактор и сохранение, карту и слайды, автономные экспорты, импорт, ошибки хранилища, мобильную вёрстку, клавиатуру, три режима ИИ, просмотр/подтверждение/отмену, авторизацию, CORS, валидацию, таймауты, лимиты и недоступный провайдер. **Ответы провайдера в автоматических тестах синтетические** (`tests/fixtures/provider.cjs`); платных сетевых запросов тесты не выполняют. Это не проверка действительности ключа, качества реального ответа модели или публичного развёртывания. Для этого после настройки нужен реальный запрос по инструкции развёртывания.
