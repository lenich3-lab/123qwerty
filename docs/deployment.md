# Развёртывание ИИ-генерации

## Вариант: весь проект на Render

В репозитории подготовлен `render.yaml` для Node-сервиса. Если используете другой хостинг, ему нужны Node.js 24.5+, команда `npm start`, переменная `PORT` и HTTPS.

1. В Render создайте Blueprint из репозитория `lenich3-lab/123qwerty`, ветка `main`, используя `render.yaml`.
2. В защищённых переменных сервиса задайте:
   - `TUTOR_AI_API_KEY`: действующий ключ OpenAI API с доступной моделью и настроенным биллингом.
   - `TUTOR_AI_ACCESS_CODE`: свой случайный код доступа длиной от 12 символов. Он потребуется пользователям генерации в пилоте.
3. Конфигурация задаёт `HOST=0.0.0.0`, `NODE_ENV=production` и `TUTOR_AI_MODEL=gpt-4.1-mini`. При необходимости выберите другую доступную вам модель с поддержкой Responses API и строгого JSON Schema.
4. Запустите развёртывание и дождитесь готовности сервиса. Доступность бесплатного тарифа и условия хостинга проверяются в интерфейсе хостинга.
5. Откройте выданный хостингом адрес приложения. В разделе «Создать с ИИ → Подключение ИИ» оставьте адрес сервера пустым и введите ваш код доступа.
6. Если раньше работали на GitHub Pages, перенесите библиотеку через экспорт/импорт JSON: хранилище браузера привязано к адресу сайта.

`render.yaml` — подготовленная конфигурация, не свидетельство успешного размещения. Для подключения репозитория и ввода секретов нужен доступ владельца к хостингу.

## Если интерфейс остаётся на GitHub Pages

1. Разместите Node-сервис по инструкции выше.
2. Оставьте `TUTOR_AI_ALLOWED_ORIGINS=https://lenich3-lab.github.io`. Это origin, без пути `/123qwerty/`.
3. На Pages откройте «Создать с ИИ → Подключение ИИ» и укажите HTTPS-адрес сервиса (без `/api/ai/generate`), например адрес, который выдаст ваш хостинг. Реального адреса сервиса в репозитории нет.
4. Нажмите «Проверить подключение», затем введите код доступа. Ключ OpenAI остаётся только на сервере.

Если origin другой, укажите его в `TUTOR_AI_ALLOWED_ORIGINS`; несколько origin разделяются запятыми. Не используйте `*`. После изменения переменных перезапустите сервис.

## Реальная проверка после подключения

1. `/api/ai/status` должен вернуть `configured: true`. Это показывает наличие конфигурации, а не действительность ключа и не доступный баланс.
2. В интерфейсе выберите «Один урок», нажмите «Заполнить пример» и «Подготовить материал». Этот шаг выполняет реальный оплачиваемый запрос к OpenAI.
3. Проверьте цель, конкретные задания/решения, сумму минут, домашнюю работу и рекомендации. Просмотр не должен изменять старые уроки.
4. Добавьте материал в библиотеку и проверьте карту, слайды и повторное открытие страницы.
5. Отдельно проверьте серию и программу. У серии должны быть независимые уроки; у программы — модули и корректная сумма количества занятий.

Ошибки ключа, баланса, недоступной модели и подключения показываются явно. Приложение не подставляет готовый пример вместо неудачного ответа ИИ.

## Для облачной среды Codex

Требование `TUTOR_AI_API_KEY` добавлено в черновик настроек среды с HTTPS-направлением `api.openai.com`. Введите значение через защищённые настройки, сохраните изменения и опубликуйте среду. После применения перезапустите `npm start` и повторите реальную проверку. Не присылайте значение ключа в чат.

В локальной облачной машине с `HOST=127.0.0.1` код доступа необязателен. Для публичного хостинга задавайте его в защищённых переменных самого хостинга: это локально читаемый серверный секрет, а не подставляемый прокси-ключ для внешнего API.

Не открывайте сервер с общим ключом для неограниченной аудитории: текущий общий код и лимиты предназначены для пилота с доверенными пользователями. Перед массовым запуском нужны индивидуальные аккаунты, квоты и общее хранилище лимитов.
